# Idea Planet 产品核心

> **状态：** 2026-09-06 讨论确认的产品工作方向。本文固化本次 session 的共识，作为后续产品讨论、文章、介绍和功能判断的优先参考。它描述核心方向，不替代未来针对具体版本的需求文档，也不代表市场验证已经完成。

## 一句话定位

Idea Planet 服务那些高频吸收信息、持续产生想法，并且需要把想法变成内容、判断和行动的人。

## 用户真正的问题

用户每天在 X 等信息流中看到很多有价值的内容，也会点赞、收藏、回复和表达认同。但这些内容往往停留在当下的感觉里，很少真正进入用户自己的观点、作品、决定和行动。

核心问题不是“没有地方保存内容”，而是：

> **我积累了很多有价值的东西，却没有持续把它们变成自己的产出。**

用户也不一定愿意每天打开一个应用，逐条整理自己的思想。因此，Planet 不应把用户的主要任务设计成维护收件箱或知识库。

## 核心价值

对外表达优先使用下面这段话：

> 你收藏过那么多好内容，却很少真正变成自己的东西。Idea Planet 会把你在 X 上看过、写过和实践过的内容交给一个逐渐了解你的 Agent；当你准备写文章、判断一个问题或推进一个计划时，它会从你的长期积累中找出真正相关的想法，帮你形成可以继续使用的草稿、判断和下一步行动。你不用整理知识库，也不用每次重新解释自己。把你的第一批想法带进来，看看它能替你创造什么。

更短的表达是：

> **让过去的想法，在今天继续为你创造。**

这句话是产品愿景和核心承诺。它强调的不是保存、记忆或拥有 Agent，而是过去的个人积累在今天产生了可感知的结果。

## 产品的基本关系

Idea 是产品的核心对象。

- 用户看到的外部内容是 Idea 的起点；
- 用户的理解、重述、反驳和新判断是新的 Idea；
- 用户的行动、实践结果和新问题也属于 Idea；
- 一个 Idea 可以继续产生新的 Idea，并保留来源、关系和变化过程。

Planet 是属于用户的长期思想空间。它不是必须清空的 Inbox，也不要求用户把所有内容整理成严格的分类系统。它保存用户的积累，让这些积累以后可以被调用、连接和重新理解。

Agent 是主要的价值创造来源。Agent 不是孤立的聊天机器人，而是从同一个 Planet 中以不同角度工作的能力。用户可以创建或定制情感 Agent、写作 Agent、产品 Agent、学习 Agent、行动 Agent 等，让它们拥有不同的目标、语气、判断方式和权限，但共享用户自己的长期 Idea。

Agent 的输出也应该能够回到 Planet，成为新的 Idea，并与来源、任务、实践和结果建立关系。用户的表达、选择、行动和反馈越多，Agent 对用户的理解就越有上下文。

## 用户获得的结果

所有功能最终都应服务于具体结果，而不是增加更多存储或更多配置。主要结果包括：

- 从自己的长期积累中写出更像自己的文章、帖子和其他内容；
- 在做决定时调用过去的判断、经验和已经验证过的想法；
- 把模糊的灵感推进成可执行的计划和低成本实验；
- 发现长期反复关注的主题、观点变化、矛盾和未完成的行动；
- 在合适的时刻重新遇见一条旧 Idea，让它参与当前的思考和对话。

用户付费的原因不是“拥有一个记忆库”或“拥有很多 Agent”，而是产品帮助用户更快完成重要的创造、判断和行动，或者产出原本难以独立完成的结果。

## 第一目标用户

第一阶段优先服务：

> **AI / 技术领域的独立创作者、产品人、创业者和重度知识工作者。**

他们通常：

- 高频阅读、收藏、点赞和表达；
- 需要持续写作、研究、做产品判断或推进项目；
- 拥有大量零散想法，但难以长期调用；
- 能感受到遗忘、重复思考和思考断裂带来的损失；
- 愿意为提高创造效率、判断质量和持续产出付费。

可以用下面这句话快速判断一个人是否属于首批用户：

> **他是否持续输入、持续输出，并且因为忘记自己的好想法而损失产出？**

研究者、设计师、教育者、顾问等人群可能是后续扩展用户。情感 Agent 和个人成长方向可以发展，但初期需要更高的信任、隐私和安全要求，不作为第一验证重点。

## “每天打开 Planet”的重新理解

Planet 不需要依赖用户每天主动整理内容来证明价值。更理想的体验是，用户因为今天有一件值得关注的事而打开，或者在其他工作场景中直接使用 Agent：

- 今天最值得重新看的一个 Idea；
- 最近正在形成但还没有说清楚的一个观点；
- 和当前项目有关的一条旧想法；
- 一个尚未完成的行动或实验；
- 过去一段时间观点发生变化的地方；
- 一条可以继续写、继续试或继续讨论的方向。

Planet 的价值不是让用户处理更多内容，而是让过去的自己在当前时刻发挥作用。

## 功能判断标准

以后评估任何功能、Agent 或产品方向时，优先问：

1. 它是否帮助目标用户调用过去的 Idea？
2. 它是否让用户更快或更好地产生内容、判断或行动？
3. 它是否减少了用户必须亲自整理和维护的工作？
4. 它是否让用户感受到自己的长期积累正在产生复利？
5. 它是否建立在用户拥有和可控制的个人 Idea 之上？

如果一个功能只是增加收藏数量、页面复杂度或 Agent 数量，却不能帮助目标用户形成更好的结果，就不应成为优先事项。

## 对外写作时应保持的顺序

介绍产品时，先讲用户的问题和可以得到的结果，再讲 Agent 和 Planet 的理念：

```text
我收藏了很多东西，却没有变成自己的产出
        ↓
Planet 在我需要时调用过去的想法
        ↓
我更快写出内容、做出判断、推进事情
        ↓
我的积累持续产生复利
```

“自定义 Agent”“一切皆为 Idea”“让 Agent 越来越懂你”是重要的产品理念和实现方式，但不应取代对用户结果的直接说明。

## 当前最重要的验证方向

下一步不应先验证用户是否喜欢大量 Agent，而应验证：

> **在一个真实的写作、决策或项目推进任务中，Agent 能否利用用户过去的 Idea，帮助他完成一个原本很费力、但确实值得付费的结果？**

第一批验证可以优先围绕创作和输出展开，因为结果清晰、使用频率高，也更容易观察用户是否愿意持续使用和付费。平台的更广泛能力，应从这个具体结果逐步长出来。
