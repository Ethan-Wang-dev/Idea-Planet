# MVP 0.1 实现范围

这是首轮 MVP 的历史范围。当前实现状态以 07-backend-agent-roadmap.md 为准，默认本地单人运行。

## 验证目标

用户能从 X 保存内容，回到 Planet 观察自己的兴趣，给 Idea 添加轻量标签，保留完整材料或重点，并通过 Sweep 或 Idea 两种动作继续整理和发展内容。

## 本轮实现

- 本地单用户网站和 Chrome Manifest V3 插件。
- 插件监听 X 自带的 Like 和 Bookmark 点击；点击后自动采集当前帖子并显示飞入星球的反馈动画。历史同步暂不实现。
- 插件也监听发布和回复完成后的新帖子：自己的发帖、回复会自动保存；回复携带原帖关系，原帖不存在时一并保存，已存在时复用原帖记录。
- Like/Bookmark 也支持 X Article：识别 Article 链接与长文容器，正文保存为 `contentType: article`，网页卡片显示 Article 标识。
- 回复框的提交按钮通常位于原帖 `article` 外，因此发布按钮使用全页面监听；打开回复框本身不会采集，真正点击 Post/发布后才采集新出现的回复。
- 发布也支持 macOS `Cmd+Enter` 和 Windows/Linux `Ctrl+Enter`；普通 Enter 只换行，不会触发采集。
- 插件离线时暂存，连接本地网站服务后重试。
- 所有采集内容默认直接进入 Planet，不建立需要用户处理的 Inbox。
- 手动粘贴全文、来源链接和可选备注，作为无需 X 即可验证的入口。
- 保留完整原文；重点、个人想法、行动、结果和新问题都作为 Idea 延伸保存，不覆盖原文。
- 回顾、保留、放下及恢复；写自己的想法并保留来源关系。
- 两种核心动作：Sweep（降低内容存在感）和 Idea（从当前内容继续产生自己的 Idea）。
- 日记式时间线、全文搜索、JSON 导出备份。
- 清洁的 Idea-first 界面：左侧承载 Planet、标签和看板，右侧空间主要呈现 Idea。
- 轻量标签与标签组合视图：首版支持 Action、Longterm、Method、Question、Reference、Emotion，并允许用户添加标签。
- 一个 Idea 可以继续产生新的 Idea，并与父 Idea 建立关系；用户的理解、长期观点、行动和实践结果都保留为 Idea。
- 内置少量示例数据用于首次体验；真实内容由用户主动录入或通过插件送入。

## 明确边界

- 这是可运行的本地闭环版本，尚不是可公开托管的多用户 SaaS。无账户、云端同步和服务端定时推送。
- 提醒在网站打开时检查；日历导出供用户自行导入日历。关掉网页不会由网站发送后台系统通知。
- 插件只读取用户浏览器已呈现的帖子；不承诺同步历史点赞、历史书签、折叠全文、图片文字、视频或完整线程。
- 自动采集只针对用户在页面上新点击的 Like 和 Bookmark；不能把它表述为已经获取了用户的全部 X 书签或点赞。
- 采集正文优先使用帖子正文节点，并过滤作者重复、翻译提示、Quote、Relevant、View quotes、Views、数字计数和操作按钮文本；原始链接仍然保留。
- 如果帖子显示 `Show more / 显示更多`，采集会先展开当前帖子，等待正文更新后再保存；插件弹窗也提供“重新采集当前帖子”来补全旧记录。
- 不自动操作 X 账户，不使用用户的 X 登录凭据，也不获取受限内容。
- 首版不调用 LLM：先验证 Planet、标签和 Idea 延伸闭环。Agent 后续可判断低价值密度内容、建议标签、生成下一步 Idea；不替用户直接定义价值。
- 放下先作为可恢复状态，便于纠正误操作；不影响 X 原帖的点赞或书签。

## 后续发布前的工作

- 用真实登录的 X 页面验收选择器和各类长帖；当前可用模拟页面验证插件事件与采集链路。
- 完善本地 SQLite 持久化、导入恢复和用户自配模型。
- 再根据真实使用反馈决定是否增加 LLM 筛选、分类、关联或外部提醒。

## 验收路径

1. 启动网站，新保存一段全文，刷新后依然存在。
2. 在回顾中保留、放下并恢复内容。
3. 针对原文写出自己的想法，在时间线中同时看到两者。
4. 从完整提示词继续产生一个自己的 Idea，并保留来源关系。
5. 配对插件，采集内容进入网页；服务不可用时留在插件待发送队列。
6. 在全部收藏中找到所有已采集书签；Like 候选能由用户主动保留或放下。
