# Idea Planet · 开源方向决策

更新时间：2026-09-07

## 当前决定

Idea Planet 现阶段按开源项目推进，暂不以商业化和收费系统作为主要目标。

这不意味着停止使用域名、Cloudflare 或 Zeabur。它们保留为项目的公开入口和体验基础设施：

- **域名（NameSilo）**：项目官网、文档、在线 Demo 和后续公共服务的统一入口。
- **Cloudflare**：DNS、HTTPS、CDN、缓存和基础防护。
- **Zeabur**：官方在线 Demo、测试环境和参考部署，用于让用户无需本地安装即可体验项目。

## 方向原则

开源的目标不是先决定代码许可证或追求 GitHub Star，而是通过公开产品获得真实用户反馈：

```text
公开产品 → 真实使用 → 用户反馈 → 需求验证 → 持续迭代
```

当前优先验证：

1. 用户是否能够顺利安装或直接体验；
2. 用户是否能完成“采集 → 回顾 → 延伸 → 召回”的核心闭环；
3. 哪些问题和功能会让用户持续使用并主动反馈；
4. 项目的开源文档、部署方式和 API 是否足够清晰。

## 外部 Agent 与工作流接入

Idea Planet 的核心不是成为一个开发者工具，也不是成为 Codex 或 Claude Code 的附属知识库。核心仍然是让用户长期积累的 Idea 在写作、判断、研究和行动时产生结果。

对于 AI / 技术创作者、产品人和创业者，Codex、Claude Code 等编码 Agent 可能是重要的工作入口之一。Idea Planet 应该进入用户已经在发生工作的场景，但不应因此把产品重定位为 coding assistant。

优先级如下：

1. **MCP Server**：作为 Codex、Claude Code 等 Agent 的统一工具入口；
2. **CLI**：方便本地脚本、终端工作流和 CI 使用；
3. **HTTP API**：供网页、插件、MCP Server 和其他客户端复用。

第一版 MCP 工具应围绕用户自己的上下文，而不是暴露全部数据库操作：

- `search_ideas`：按任务目标搜索相关 Idea；
- `get_idea`：读取单条 Idea 及其来源和关系；
- `recall_context`：生成带引用的任务上下文包；
- `save_idea`：在用户明确确认后保存新的 Idea；
- `create_relation`：记录新 Idea 与既有 Idea 的延伸、支持或冲突关系；
- `record_decision`：记录编码过程中的方案、取舍和结果。

默认应优先提供只读能力，写入操作需要明确确认。MCP、CLI 和网页都应复用同一套后端权限、用户隔离、审计和数据模型，不能为不同客户端复制一套业务逻辑。

这会让 Planet 的长期积累能够参与更多真实工作场景：用户可以在写作、研究、产品判断、编码或行动推进时召回过去的想法，并把新的结果写回 Planet。

## 部署策略

优先采用“开源核心 + 官方在线体验”的方式：

- 自托管用户通过 Docker 或文档在自己的环境运行；
- 官方 Zeabur 环境提供稳定、可重置的公开 Demo；
- Demo 不保存敏感的真实用户数据，不公开生产密钥；
- Demo 应设置合理的限流、示例数据和数据重置机制；
- 域名和 Cloudflare 配置与具体托管平台解耦，未来可以迁移到其他平台。

如果项目暂时没有在线体验需求，可以只保留域名，并使用 Cloudflare Pages 或 GitHub Pages 托管官网和文档；不需要为了“开源”维持复杂的长期运行服务。

## 后端影响

后端继续按可自托管、可迁移的方式建设：

- 所有密钥、数据库连接和平台配置使用环境变量；
- 不把 NameSilo、Cloudflare 或 Zeabur 的具体配置写死在业务代码中；
- 提供 Docker 构建和部署说明；
- 官方 Demo 与用户自托管环境使用同一套核心代码；
- 继续隔离认证、数据存储、模型 Provider 和任务执行层，便于不同环境部署。

商业化相关的订阅、credits 和账单设计暂时只作为未来假设保留，不作为当前版本的交付目标。相关内容见 [05-business-model.md](./05-business-model.md)，在真实用户和使用数据出现后再重新评估。

## 当前不做的事情

- 不为了收费而提前实现复杂的订阅、支付和 credits 系统；
- 不把官方 Demo 当作唯一运行方式；
- 不公开 API Key、数据库、用户数据或生产管理权限；
- 不仅以 Star 数量判断项目是否成功。
